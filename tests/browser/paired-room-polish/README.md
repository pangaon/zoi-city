# Paired guest room verification

Run from repository root with installed playwright-core and local Chromium:

```sh
node --test tests/unit/room-navigation-model.test.mjs tests/unit/furnished-concert.test.mjs tests/unit/paired-room-camera.test.mjs tests/unit/room-scene.test.mjs
OUTPUT_DIR=/tmp/paired-room-review node tests/browser/paired-room-polish/verify.cjs
```

The fixture creates its own local HTTP server. Toronto uses the real event page; Montréal mounts the real shared renderer using its published plan module. It blocks outside requests and creates no production records. Eight journeys cover each city at 390×900 and1440×900 with reduced motion, plus320×700 and844×390 with normal motion. Test motion values are Playwright enums, not simulated animation source. Three source-edge/alphanumeric table selections per journey must retain exact identities, safe selectable labels and existing selection meaning. CDP dispatches actual touch input and desktop uses real mouse input; canvas drag must not reselect a table. The finder contains every source ID and keeps an existing selected identity visible outside the finder. Open/close, Escape, fullscreen exit, source colours, readable desktop118/102 coverage, and unobstructed label/control hit targets are checked. Screenshots include oblique, seated, overview and focused source-edge views.

Optional focused dimensions:

```sh
ROOM_CASES_JSON='[{"width":320,"height":700,"motion":"reduce"}]' OUTPUT_DIR=/tmp/paired-room-phone node tests/browser/paired-room-polish/verify.cjs
```

Software WebGL screenshot rendering can take several minutes. The fixture is sequential and closes its own browser/server. Physical phones, actual venue equipment/sightlines, live inventory, sponsorship approval and payment operations remain separate gates.
