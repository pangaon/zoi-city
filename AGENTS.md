# Zoi delivery requirements

For Zoi product, design, enrichment, integration or QA work, read
[the Zoi delivery brief](docs/specialists/zoi-delivery/SKILL.md) and the relevant
role in its references before implementation. These are the user's persistent
product requirements; current user instructions and authorization remain authoritative.

The full requested scope is tracked in [docs/recovery-scope.json](docs/recovery-scope.json).
Do not silently drop earlier work when a new example or defect arrives.
Apply shared corrections to every applicable family, then verify representative
and sparse records. A curated showcase is not evidence of category-wide coverage.

Preserve concurrent work. Agree on file ownership before editing another
specialist's files. Four concurrent slots include the lead; use the authorized
specialists for independent work and keep integration/release ownership clear.

Never call a listing or feature complete because it returns HTTP 200, renders a
hero, or passes unit tests alone. Record source, rendered, and exercised-journey
evidence separately. Explain actual production capability and remaining gaps in
plain English. Do not promise zero defects or provider capabilities that are not connected.
