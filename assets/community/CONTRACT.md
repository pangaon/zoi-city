# Community foundation — locked client contract, implementation in progress

All new RPCs below return JSON `{ok:true,...}` or a database error. Publish/media contract is owned by the media specialist and will be appended separately. No demo content or synthetic counts. Authenticated identity is the existing profile ID, never auth-user UUID. Public authors expose only explicitly chosen social fields. A public post is public: block filters authenticated views/interactions, not anonymous internet access.

## Public models

Profile: `{id,handle,display_name,avatar_url,bio,city,country,interests,version,following_count,follower_count,post_count,followed,mine}`. `id` is existing user_profiles.id. No email, phone, auth UUID, legal name fields or private preferences. Profiles without configured public identity render `handle:null,display_name:'Community member',avatar_url:null,bio:'',city:null,country:null,interests:[]`. Public authored posts stay accessible unless deleted/moderated; unset public identity does not infer a hometown from private account data.

Post: `{id,body,created_at,author,listing,intent,topics,city,country,media,likes,comments,liked,saved,mine,accepted_comment_id,context_version,ranking_reasons}`. `author` profile projection with id/handle/display_name/avatar_url/city/country only. `listing` null or `{id,name,slug,entity_type}` for a currently published/nonhidden tagged business/place. `intent` question/recommendation/moment/event; legacy defaults moment, topics[]. `likes/comments` are actual visible counts; `ranking_reasons` string array, not invented engagement. Media normalized objects `{id:null|uuid,type:'image'|'video',url,poster_url:null|string,mime_type:null|string,width:null|number,height:null|number,duration_seconds:null|number,alt:string}`; watch only verified video objects, never arbitrary image URLs or inferred reels.

Comment: `{id,post_id,body,created_at,author,mine,accepted}`. Same minimal author shape. Counts and reads omit blocked authors for current authenticated viewer.

Topics fixed allowlist: `food,travel,business,careers,culture,language,music,faith,sport,family,local,community`. Max5 authored post topics, max8 chosen profile interests/preferences. Profile interest opt-in is public; feed preferences private. City/country free text <=120 each, no GPS stored.

## Feed and profiles

- `community_feed(p_mode text='for_you',p_limit integer=20,p_offset integer=0,p_as_of timestamptz=null,p_profile uuid=null,p_topic text=null,p_query text='')` → `{ok,mode,as_of,posts,next_offset,ranking_rules}`. Modes for_you/latest/following/saved/questions/profile/watch/near_me. limit1..50, offset0..1000; query<=100 literal substring. First request as_of null; paginate using returned as_of and next_offset (nullable). Following/saved/near_me require auth. near_me uses explicitly enabled chosen locality preferences; absent locality returns empty with honest ranking explanation. profile requires p_profile. Latest/profile/saved are chronological; for_you/questions/watch/near_me use documented deterministic relevance and author-diversity, no paid ranking. Recent candidate bound1500; saved/profile use their own bounded history rather than silently dropping all old saved posts. `ranking_rules` string array suitable for “How this feed works”.
- `community_post_get(p_post uuid)` public → `{ok,post}` exact visible Post or null. Blocks/status apply; simple feed mute does not prevent opening an explicit link.
- `community_me()` auth → `{ok,profile,preferences,counts,blocked,muted,topics}`. profile own configured shape (or default), plus own-only `avatar_media_id` for preserving unchanged avatar on edits; preferences `{topics,city,country,locality_enabled,version}`; counts `{following,saved,unread_notifications}`; blocked/muted minimal public profile arrays; topics allowed array. On no profile setup, profile.version=0 and handle=null. No automatic publication of existing private account fields.
- `community_profile_get(p_handle text=null,p_profile uuid=null)` public → `{ok,profile}`. Exactly one handle or ID required. Missing/blocked configured profile returns profile:null. Own caller receives own profile. Does not include posts; use feed mode profile with returned ID.
- `community_profile_save(p_expected_version integer,p_data jsonb)` auth → `{ok,profile}`. Data `{handle,display_name,bio,city,country,interests,avatar_media_id:null|uuid}`. Handle lowercase `[a-z0-9_]{3,30}` unique, reserved admin/support/zoi names rejected; display1..80, bio<=400, optional city/country<=120, interests allowlist<=8. Explicit profile creation expected0, edits expectedcurrent. Avatar must be a finalized owned image asset from media workflow; null removes. Initials work without avatar. Response avatar_url server-derived only, plus own-only avatar_media_id. No external arbitrary avatar URLs.
- `community_follow_set(p_profile uuid,p_follow boolean)` auth → `{ok,profile_id,following,follower_count}`. Desired state, repeat-safe; no self-follow or blocked relationship. Only configured public profiles can be followed. Actual notification to followed account on new follow.
- `community_saved_set(p_post uuid,p_saved boolean)` auth → `{ok,post_id,saved}`. Desired state, repeat-safe, private; post must be visible. Does not notify author.
- `community_preferences_save(p_expected_version integer,p_data jsonb)` auth → `{ok,preferences}`. Data `{topics,city,country,locality_enabled}` validated limits above; explicit chosen locality only, no browser geolocation assumption.

## Interactions and controls

- `community_like_set(p_post uuid,p_liked boolean)` auth → `{ok,post_id,liked,likes}`. Desired state, repeat-safe, backed by existing likes storage. New like generates one real in-app notification; no self notification.
- `community_comments(p_post uuid,p_limit integer=30,p_offset integer=0)` public → `{ok,comments,next_offset}`. limit1..50, offset0..1000; actual replies with block/moderation guards.
- `community_comment(p_post uuid,p_request uuid,p_body text)` auth → `{ok,comment}`. Stable UUID request, exact original post/body retry; trim body1..500. Existing durable comment storage; no notification sends outside app.
- `community_accept_answer(p_post uuid,p_comment uuid|null,p_expected_version integer)` auth question author only → `{ok,post_id,accepted_comment_id,context_version}`. Same question's visible reply, independent commenter; null clears. This marks usefulness, not a verified factual answer. Accepted answer generates real notification. Intent must be question.
- `community_block_set(p_profile uuid,p_blocked boolean)` auth → `{ok,profile_id,blocked}`. Desired state, no self block; removes mutual follows and hides account content/notifications in authenticated views. No notification to blocked person.
- `community_mute_set(p_profile uuid,p_muted boolean)` auth → `{ok,profile_id,muted}`. Private desired state, suppresses author in viewer's feeds/notifications; no notification.
- `community_report(p_post uuid,p_reason text,p_details text,p_request uuid)` auth → `{ok,report_id,status:'pending'}`. Reason spam/scam/harassment/hate/privacy/other, details<=1000, stable UUID exact request. Captures reported public content for restricted platform moderation. It does not automatically delete or claim human review completed.
- `community_notifications(p_limit integer=30,p_offset integer=0)` auth → `{ok,notifications,next_offset,unread_count}`. Notification `{id,kind,actor,post_id,comment_id,created_at,read_at}` kind follow/like/comment/accepted_answer; own recipient only, visible unblocked/nonmuted interactions, no fake notifications.
- `community_notifications_read(p_ids uuid[])` auth → `{ok,updated,unread_count}` own IDs max100; repeat-safe.

Existing `feed_like`, `feed_comment`, `feed_comments_list`, `feed_list` and `feed_delete` keep their signatures but gain visibility/block/moderation guards; legacy reads cannot bypass those controls. Actual signatures/return shapes being verified from live metadata before wrappers. New public post reads and author profiles never return legacy account-contact fields.

Platform-admin-only `community_reports_queue(p_limit integer=30,p_offset integer=0)` returns `{ok,reports}` (pending private report records including captured content). `community_reports_review(p_report uuid,p_action text,p_note text)` accepts dismiss/hide and a required1..1000 character note, returning `{ok,report_id,status}`. Completed reviews are immutable; exact retry is accepted. Verified existing zoi.is_admin checks the configured platform administrator allowlist; ordinary business workspace administrators cannot moderate strangers. No external emails, push, payments or automatic moderation claims.

## Private media and atomic publication (media migration follows foundation)

`community-media` Edge function must deploy with JWT verification disabled because public GET has explicit database visibility authorization; every upload/discard independently validates the user token with Auth. POST `?action=upload` is multipart `{file,request_id:UUID,purpose:'post'|'avatar'}` with Bearer session and publishable apikey. Receipt `{ok:true,asset:Media}`. JPEG/PNG/WebP <=8MiB; MP4 with H.264 video (optional MP4A audio) <=32MiB, <=120seconds; no transcoding. Server checks binary container/dimensions/codec metadata; unsupported files rejected. Images <=8192px each axis and <=40million pixels. Stable request UUID + identical file/purpose retries return identical asset; modified bytes rejected. Client retains local draft/file preview while uploading. Max50 uploads/day/member. Never upload a different file under an existing request.

Assets remain in a private immutable bucket. Stable Media.url is the public Edge URL `/functions/v1/community-media?asset=UUID`; GET only redirects to a 60-second storage URL when attached to a currently visible post or selected public avatar. Finalized unattached assets remain private. Owner local preview uses selected file. Already issued storage links may work until their short expiry after deletion/hiding; public content can be copied.

`community_publish(p_request uuid,p_body text,p_media uuid[] default '{}',p_listing uuid default null,p_context jsonb default '{}')` → `{ok:true,id:postUUID,request_id:matchingUUID}`. Body trimmed1..1000. Media max4 images OR1 video, owned finalized post-purpose assets. Context foundation intent/topics/city/country plus optional media_alts object {assetUUID:'authored description'} (max500 characters each, only attached IDs). Descriptions are preserved per post and included in Media.alt. Listing must currently be published/nonhidden. One transaction creates post+context+durable exact request receipt; repeat identical request never creates a duplicate even after original post deletion. Changed payload rejected. Retain frozen request on uncertain response. Success receipt identifies publication; use community_post_get for current visibility. Text-only works with empty media.

Discard: authenticated POST `?action=discard` JSON `{asset_id}` → `{ok:true,id}`. Attached/profile-used assets cannot be discarded. Orphan cleanup is service-only POST `?action=cleanup`, bounded100 assets older than24hours per invocation; closes asset first, deletes storage objects, acknowledges deletion. Deployment must schedule this existing provider endpoint (no client service secret). Until scheduled, cleanup is manual service invocation and UI must not claim automatic deletion completed.

Shared web helper `assets/community/media-client.mjs`; native uses the same transport/receipt validation. Media.alt is explicitly authored via p_context.media_alts; absent descriptions default empty, never inferred.
