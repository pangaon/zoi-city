# Artist appearances and private trips — candidate

No appearance is inferred from hometown, names, biographies, free-form tour text or nearby map points. An immutable appearance proposal contains an actual public artist/creator ID, actual public event ID, explicit start/end/timezone and HTTPS source URL. Its status becomes confirmed only when owner/admin accounts for **both** saved owner workspaces confirm those same terms. If one workspace owns both listings, its authorized operator may confirm both. This is confirmation by those workspace operators, not independent fact checking, legal agreement or a ticket purchase. Source URL is supplied by operators and displayed with attribution. Any side can withdraw. To change the terms, withdraw and create a new proposal.

All responses `{ok:true,...}`; identity is `zoi_me.profile.id`. Public reads filter published/nonhidden listings and current ownership against saved snapshots; ownership transfer invalidates discovery and further confirmation. History stays with original workspaces. Never show private trip data to workspace operators. No notifications, paid providers or ticket/booking mutation.

Public RPCs:
- `trip_discover(p_query text='',p_country text|null=null,p_type text|null=null)` → `{ok,listings:[{id,name,slug,entity_type,city,country}]}`. At most30 real public records; query<=100, country exact e.g. Greece; type event/artist/creator/business/organization/travel_place or null. This is name discovery, not an appearance match. Canonical redirect home link `/p/ENCODED_SLUG`.
- `artist_shows(p_artist uuid)` → `{ok,shows:[{id,artist_id,event_id,starts_at,ends_at,timezone,source_url,updated_at,artist_name,event_name,slug,city,country}],confirmation:'event_and_artist_workspace'}`. Upcoming mutually confirmed, current owner/public visibility only, max100. Dates identify the artist appearance, not necessarily the whole event.

Owner/admin operator RPCs:
- `appearance_operator(p_workspace uuid)` → `{ok,appearances,owned,audit}` latest100 appearance/audit records; owned public artist/creator/event rows `{id,name,entity_type}`. Appearance row `{id,artist_id,event_id,artist_workspace,event_workspace,starts_at,ends_at,timezone,source_url,event_confirmed_by,artist_confirmed_by,status,version,created_by,initial_data,created_at,updated_at}` plus artist_name,event_name,currently_visible.
- `appearance_propose(p_id uuid,p_data jsonb)` → `{ok,appearance}`. New stable UUID, exact initial-data retry (creator only). Data `{artist_id,event_id,starts_at,ends_at,timezone,source_url}`. At least one current owner/admin; auto-confirms only that actor's authorized side(s). Source HTTPS<=2000, explicit finite times; duration>0<=7days; max30 proposals/profile/day.
- `appearance_decide(p_id uuid,p_expected_version integer,p_action 'confirm'|'withdraw')` → `{ok,appearance}`. Optimistic version, own saved workspace owner/admin; confirmation rechecks current owner/public visibility. Terminal withdrawal; no external messages.

Private customer RPCs:
- `trips_mine()` → `{ok,trips}` active own trips max30 with item_count.
- `trip_save(p_id uuid,p_expected_version integer,p_data jsonb)` → `{ok,trip}`. New stableUUID expected0 exact initial retry; existing expectedcurrent. `{name,timezone,notes}` name1..160, IANA timezone, notes<=4000. Row `{id,profile_id,name,timezone,notes,version,initial_data,archived,created_at,updated_at}`.
- `trip_get(p_trip uuid)` → `{ok,trip,items,audit,server_now}`. Own only; active items sortedtime max100; latest100 audit. Item row below plus `listing_name,slug,entity_type,listing_available,appearance_confirmed,time_conflict`. Hidden/unpublished listing names/links withheld, own planned notes retained. `appearance_confirmed` null for manual stop, boolean for linked appearance. Time conflicts mean overlapping planned intervals only; no transit estimates.
- `trip_item_save(p_trip uuid,p_id uuid,p_expected_version integer,p_data jsonb)` → `{ok,item}`. `{listing_id,appearance_id:null|uuid,starts_at,ends_at,timezone,notes}`. Actual public listing required. If appearance_id supplied, server requires confirmed current appearance for that listing and derives dates/timezone from its record, ignoring client times. Otherwise explicit finite timestamps, valid IANA zone, duration>0<=7days. notes<=2500. Own active trip, max100 active items; expected0 stable UUID + exact initial-data retry. Row `{id,trip_id,listing_id,appearance_id,starts_at,ends_at,timezone,notes,version,initial_data,removed,created_at,updated_at}`.
- `trip_remove(p_trip uuid,p_item uuid|null,p_expected_version integer)` → `{ok,record}`. p_item null archives own trip, otherwise removes item with matching own trip/version. Retains private audit; read current state after an uncertain response rather than replaying changed version.

All trip tables private RLS + no direct grants; restricted security-definer RPCs. Approved appearances are public commitments by platform account operators, not identity-verified artist credentials. Existing artist tour JSON remains unverified and excluded. UI must show planned vs confirmed appearance vs actual booking separately. Home links offer existing configured ticket/booking actions; saving does not reserve. Nearby exploration uses existing `/explore/map/` user-consent location flow/manual search, without storing device coordinates or inventing travel times.
