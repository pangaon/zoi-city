# Matter timekeeping (candidate)

Private time narratives/rates linked to existing Operations projects (legal matters) and optional tasks. No invoice, tax, payment, trust accounting, deadline calculation or legal determination. Timer duration is calculated by server timestamps; manual time is user-reported. Amounts are rate-based estimates. Distinct currencies are never summed together.

All RPCs require authenticated JWT and `{ok:true}` receipts. owner/admin/editor may create own time; viewers denied entirely. Editors see only own entries/timers/audit; owner/admin see team entries and approve/return/void. Rates/narratives stored in private new tables, never copied into generic Operations notes.

- `timekeeping_dashboard(p_workspace uuid,p_from timestamptz,p_to timestamptz)` → `{ok,role,actor_id,entries,projects,tasks,members,active_timer,active_other_workspace,totals,server_now,timer_audit}`. Range finite, >0,<=93days; max1000 rows else narrowrangeerror. Project options active; tasks active; actor_id profileUUID. Active timer own only; indicator for another workspace reveals no narrative. Entry queries use started_at in[from,to). totals grouped currency; approved-only seconds/estimated_cents.
- `time_entry_save(p_workspace uuid,p_id uuid,p_expected_version integer,p_data jsonb)` → `{ok,entry}`. New client UUID+expected0 creates idempotently using exact initial_data. Updates current own draft/returned only; result draft. p_data `{project_id,task_id:null|uuid,started_at:<ISOexplicitoffset>,seconds:<integer1..86400>,description:<1..2000>,rate_cents:<integer0..1000000>,currency:<uppercase3>,billable:<boolean>}`. End no more than60seconds in future. No overlap with another nonvoid entry or own running timer, including across workspaces. Project/task same workspace and task parentproject required.
- `time_timer_start(p_workspace uuid,p_request uuid,p_data jsonb)` → `{ok,timer}`. Same fields excluding started_at/seconds. Server creates start timestamp. Exactly one running timer per profile across allworkspaces. Stable request UUID retry returns original timer, even stopped/discarded. No automatic start on restore.
- `time_timer_stop(p_workspace uuid,p_timer uuid,p_request uuid)` → `{ok,timer,entry}`. Own timer; server elapsedseconds minimum1,max24hours; longer timer must be discarded with reason and replaced by corrected manual entry. Stable stop UUID returns same entry, never duplicate. New draft entry snapshots start metadata/rate.
- `time_timer_discard(p_workspace uuid,p_timer uuid,p_expected_version integer,p_reason text)` → `{ok,timer}`. Own runningtimer only; reason1..1000. Audit retains discardedtimer; no billable entry.
- `time_entry_transition(p_workspace uuid,p_entry uuid,p_expected_version integer,p_action text,p_reason text)` → `{ok,entry}`. submit own draft/returned→submitted; withdraw own submitted→draft; approve owner/admin submitted→approved; return owner/admin submitted→returned requiresreason; void owner/admin approved ORown draft/returned→voided requiresreason. No editing approved/submitted/voided data. Each transition increments version with actor/time before/after audit. Selfapproval explicitly visible via approved_by=actor_id, not prohibited for sole operators.
- `time_entry_history(p_workspace uuid,p_entry uuid)` → `{ok,entry,audit}` latest100 records; author or owner/admin only.
- `timekeeping_export(p_workspace uuid,p_from timestamptz,p_to timestamptz)` → `{ok,entries,totals,generated_at}` approved entries only; same author/admin scope and93dayrange, max5000rows else narrowrangeerror. Client CSV escapes fields and spreadsheet formulas. Export is timesheet data, not an invoice.

Entry `{id,workspace_id,profile_id,project_id,task_id,started_at,seconds,description,rate_cents,currency,billable,estimated_cents,source:'manual'|'timer',timer_id,initial_data,status:'draft'|'submitted'|'approved'|'returned'|'voided',version,approved_by,approved_at,created_at,updated_at}`. Dashboard adds project_title,task_title,display_name. Timer `{id,workspace_id,profile_id,request_id,initial_data,data,started_at,status:'running'|'stopped'|'discarded',version,stop_request,entry_id,finished_at}`. timer.data is validated inputmetadata only. Audit `{id,workspace_id,entry_id,timer_id,actor_id,action,reason,before_state,after_state,created_at}`. Customer/clients cannot read timekeeping.

UI date inputs must reject DST gaps/folds or ask for explicit offset. Send UTC timestamps; show display timezone. Foreground refresh reads only; a timer never auto-stops or restarts. Preserve UUIDs for uncertain explicit retry.

Dashboard server_now is an ISO server timestamp for display offset only. timer_audit is latest30 `{id,timer_id,actor_id,action,reason,created_at}` records, editorown/adminteam. Timers started on an active matter can still be stopped into historical time after that matter/task is archived; new manual time and timer starts require active parentrecords. Editing a timer-derived draft makes source=manual and retains timer_id/audit, so corrected duration is never represented as untouched server timing.
