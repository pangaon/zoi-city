# Festival sponsor and booth applications (candidate)

Organisers publish/edit/pause real sponsor or booth package offers on owned, published, nonhidden event, organisation or business listings. Customer applications are private and do not reserve capacity until approved. Approval atomically consumes package units; withdrawal/cancellation releases units. Prices are quoted amounts arranged with organiser; no online payment is collected. Accepted application terms remain the original snapshot when the offer later changes.

All RPCs return `{ok:true,...}`. Public catalog is anonymous safe; all writes/history require authenticated JWT. owner/admin manage package offers; owner/admin/editor operate private application inbox/review; applicant may read/edit own pending applications and withdraw own pending/approved applications.

- `festival_catalog(p_event uuid)` → `{ok,available,event_name,packages}`. Public active offers only while application deadline is future and event remains owned/published/nonhidden. Package rows expose id,kind,name,description,benefits[],price_cents,currency,capacity,allocated,remaining,closes_at,timezone,version. No applicant identities/contact details ever public.
- `festival_operator(p_workspace uuid,p_event uuid|null=null,p_status text|null=null,p_offset integer=0)` → `{ok,role,events,packages,applications,audit,next_offset}`. 50applications/page with next_offset;latest100audit; events include all owned public visible host listings. Packages allown workspace inclpaused; allocationscomputedapprovedunits. Applications privatefullrows.
- `festival_package_save(p_workspace uuid,p_id uuid,p_expected_version integer,p_data jsonb)` → `{ok,package}`. New stableclient UUID expected0+exactinitialdata retry; existingcurrentversion. Fields event_id,kind booth/sponsor,name1..160,description0..3000,benefits stringarraymax20x200,price_cents integer0..100000000,currencyuppercase3,capacity integer1..5000,closes_at explicitfiniteISOtimestamp,timezoneIANA,activeboolean. Publication active requires future deadline. Cannot changeevent/kind afteranyapplication; cannot reducecapacity belowapprovedunits. Editor cannot changecommercialoffers.
- `festival_apply(p_package uuid,p_expected_package_version integer,p_request uuid,p_data jsonb)` → `{ok,application}`. Data organisation1..160,contact_name1..120,contact_email1..160,category food/crafts/books/community/sponsor/other,units integer1..10,notes0..2500. StableUUIDrequest; latestoffer versionrequired; activepublicdeadline andremainingcapacitychecked, but submission doesnot holdunits. Max10newapplications/profile/day; one pending/approvedapplication/profile/package. Snapshots package terms and unitprice/currency. Creates linked private enquiry thread atomically for actual customer/operator communication, independent of general-contact opt-in.
- `festival_application_edit(p_application uuid,p_expected_version integer,p_data jsonb)` → `{ok,application}`. Own submitted application only; samecustomerfields; preserves original offer snapshot. New requested units use original unitprice; current packagecapacity rechecked; editing doesnot reserve remainingunits. Editedcustomerdata audited.
- `festival_my_applications(p_event uuid|null,p_offset integer=0)` → `{ok,applications,next_offset}` 50ownrows/page including event_name, next_offset nullable. No other customerdata.
- `festival_application_decide(p_workspace uuid,p_application uuid,p_expected_version integer,p_action text,p_reason text)` → `{ok,application}`. approve submitted→approved, decline submitted→declined, cancel approved→cancelled. Decline/cancel reason1..1000required. Approval locks packageinventory and requires originaleventstillownedvisible/published; deadline closing doesnot prevent reviewing already-submitted requests. Accepted terms snapshot unchanged.
- `festival_application_withdraw(p_application uuid,p_expected_version integer,p_reason text)` → `{ok,application}`. Own submitted/approved→withdrawn, reason1..1000; permitted evenwhenoffers/eventpaused so customer canreleaseallocation.

Application status submitted/approved/declined/withdrawn/cancelled. Row `{id,package_id,workspace_id,event_id,profile_id,request_id,initial_data,data,terms,units,total_cents,inquiry_id,status,version,review_reason,reviewed_by,reviewed_at,created_at,updated_at}`. terms snapshot `{package_version,kind,name,description,benefits,price_cents,currency,closes_at,timezone}`. Applicant identity is zoi_me.profile.id, not authUUID. `data` is normalized form fields above. Terminal records read-only; cancellation/withdrawal preserves history.

Offer edits changefuturecatalog immediately; existingapplicationterms stayfixed. UI must show current quote snapshot and status separately. Public route `/festival/?event=UUID`, authenticated own history `/festival/`, operator module `festival`. Application receipt links existing `/inquiries/?thread=UUID`; a sponsor discussion can be converted by existing Creator Studio into shared deliverable/approval workflow. No new email/push/attachment/permit-verification/checkout claims.

Event parameters name a host listing, which may be an event, organisation or business; no event-only restriction. Public package rows also include application_required:true,payment_collected:false,offer_url:`/festival/?event=HOST_UUID&offer=PACKAGE_UUID`. These are application offers with approval capacity, not checkout products.
