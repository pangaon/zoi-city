# Creator Studio contract (candidate, no provider integrations)

Private drafts become immutable customer-visible brief versions only after explicit Share. Sharing is restricted to the authenticated customer of the source enquiry and owner/admin/editor members of its immutable workspace. Customer acceptance acknowledges the brief; it is not a legal signature or payment. Draft operational notes, private documents and workspace records are never returned to the customer.

RPCs (authenticated JWT, all return `{ok:true,...}`):
- `creator_list(p_workspace uuid)` → `{campaigns,companies,inquiries,role}`; owner/admin/editor only. Reuses Operations companies/projects/tasks. Latest100 campaigns and source enquiries.
- `creator_convert(p_workspace uuid,p_inquiry uuid,p_company uuid,p_kind text,p_request uuid)` → `{campaign}`. Kind sponsorship/performance. Stable UUID idempotency; one campaign per enquiry. Creates Operations project atomically. No customer sharing yet.
- `creator_draft_save(p_campaign uuid,p_expected_version integer,p_data jsonb)` → `{campaign}`. Draft fields: title,summary,planned_fee_cents,currency; sponsorship: channels array,usage_terms,disclosure_notes; performance: venue,event_at,duration_minutes,technical_requirements. Fees are planned amounts, no money collected.
- `creator_deliverable_save(p_campaign uuid,p_id uuid,p_expected_version integer,p_data jsonb)` → `{deliverable,campaign}`. Fields title,description,channel,due_at. New deliverables use client-generated stable p_id UUID with expected_version0 (repeat exact initial p_data for retry); existing updates use current version. Creates/updates linked Operations task with audit; no deletes. Channels instagram/tiktok/youtube/podcast/blog/live/other. Deliverable changes increase campaign version; customer only sees snapshots explicitly shared.
- `creator_brief_share(p_campaign uuid,p_expected_version integer,p_request uuid)` → `{brief,campaign}`. Captures validated current draft +1..30 deliverables; immutable version. Stable retry returns same share. Version conflict rejects stale sharing.
- `creator_brief_decide(p_brief uuid,p_decision text,p_note text,p_request uuid)` → `{brief}`. Source customer only. decision accepted/changes_requested; exact idempotent retry, immutable terminal decision. Only latest shared version can be decided; older snapshots retained read-only.
- `creator_submission_send(p_campaign uuid,p_deliverable uuid,p_url text,p_note text,p_request uuid)` → `{submission}`. Operator only; requires latest shared brief accepted and deliverable present in it. HTTPS external proof link +note, no fetched content or platform verification. One pending submission per deliverable/brief; revised submission after changes_requested.
- `creator_submission_decide(p_submission uuid,p_decision text,p_note text,p_request uuid)` → `{submission}`. Source customer only; accepted/changes_requested; stable retry. Acceptance completes only its linked Operations task and records customer actor in audit.
- `creator_get(p_campaign uuid)` → `{campaign,operator,briefs,deliverables,submissions,audit,can_write}`. Operators receive private draft/current deliverables and latest100 audit. Customer receives only shared snapshots, explicitly shared deliverables and submitted proofs; no private draft/internal project fields. `briefs` newest first; `submissions` newest first. Immutable IDs authoritative.
- `creator_customer_list()` → `{campaigns}` customer-owned explicitly shared campaigns only; latest100. `/creator/?campaign=UUID` opens shared client view, `/creator/` lists own shared work.

Reads preserve history after business transfer/hiding/archive. New writes/share/decisions/submissions stop when source business is no longer published, visible and owned by the original workspace. New owner never inherits old conversations/briefs.

IDs are profile IDs, not auth UUIDs; resolve through zoi_me.profile.id. Preserve request UUID for unchanged explicit retries. No auto-send on refresh. No external email, attachment sharing, e-signature, payments, platform analytics or royalty claims.

## Concrete record shapes / limits

Campaign (operator): `{id,workspace_id,inquiry_id,customer_id,project_id,company_id,kind,request_id,created_by,draft,version,shared_version,created_at,updated_at}`. Customer campaign summary is ONLY `{id,kind,shared_version,title,inquiry_id}`. customer list rows `{id,kind,shared_version,title,status,updated_at}`. Operator list company options `{id,title}`, inquiry options `{id,subject,customer_id,updated_at}`.

Draft fields normalized: title1..200,summary0..4000,planned_fee_cents integer0..100000000 default0,currency uppercase3letters defaultEUR. Sponsorship channels0..10 enuminstagram/tiktok/youtube/podcast/blog/other default[]; usage_terms0..2000,disclosure_notes0..1000 defaultempty. Performance venue0..300,event_at ISO timestamp with explicit timezone ornull,duration_minutes integer0..1440 default0,technical_requirements0..3000 defaultempty. Share requires nonempty summary, at least1deliverable, sponsorshipchannelsnonempty and nonempty disclosure_notes, or performancevenue+eventtime+duration>=1. UI date inputs use device timezone, send ISOZ. Saved draft never auto-shares.

Deliverable (operator): `{id,campaign_id,task_id,initial_data,title,description,channel,due_at,version,created_at}`. Customer snapshot delivers ONLY `{id,title,description,channel,due_at}`. title1..200,description0..2000,channel enumlistedabovepluslive,due_at ISOtimestamp ornull. Max30deliverables. First save expected_version0 uses stable client id +exactinitial p_data. Later saves use current version.

Brief: `{id,campaign_id,version,source_version,payload,request_id,shared_by,status,decision_note,decision_request,decided_by,created_at,decided_at}`. payload `{kind,brief:<normalizeddraft>,deliverables:<customer-safe snapshots>,acknowledgment:<workflow disclaimer>}`. status shared/accepted/changes_requested. Max100sharedversions. p_expected_version is the original source_version on share retry. Sharing unchanged already-shared version rejects creator_no_changes_to_share.

Submission: `{id,campaign_id,brief_id,deliverable_id,url,note,request_id,submitted_by,status,decision_note,decision_request,decided_by,created_at,decided_at}`. URL HTTPS host only, max2000, no credentials/whitespace. note and decision_note max2000. status submitted/accepted/changes_requested. Max500submissions/campaign; pending/accepted unique per brief+deliverable. Proof links never fetched by server or presented as verified analytics.

`creator_get` operator/customer use same top-level keys; customer audit always[], deliverables sanitized snapshots, campaign excludes draft/project/company/customer identifiers. Brief history contains only explicitly shared payloads. Archived/moved task cannot be completed by customer acceptance. Read data stays available when source business hides/transfers; can_write=false, writes reject.

## Interrupted-write recovery

New web/native clients use `creator_mutation_execute(p_request uuid,p_action text,p_args jsonb)` for every write. Allowed actions are the seven mutation RPC names above. Inner request IDs are supplied by the wrapper; new deliverable `p_id` can use the outer request UUID when absent. The mutation and its receipt commit atomically. The receipt is `{ok:true,state:'saved',request_id,action,campaign_id,entity_id,version}`; version can be null for submissions. It is not a full entity response. Refresh through the existing authorized read APIs afterward.

`creator_request_status(p_request uuid,p_cancel_if_missing boolean default false)` returns the actor's saved receipt, a cancelled receipt, or `{ok:true,state:'missing',request_id}`. Missing is not proof that a request cannot arrive later. Explicit cancellation uses the same per-actor/request lock as execution: it returns an existing saved receipt or writes a tombstone that refuses later execution. It does not undo saved work. Receipts require current access to the original campaign; revocation must clear private UI while retaining only the recovery marker.

Persist only actor/request/action metadata in the platform's private request storage, before sending and with verified readback. Keep exact private arguments in memory for retry. A pending marker fences new writes until its saved or cancelled terminal outcome is verified. Lost responses, remounts, refreshes and failed status reads must not silently discard it. Browser session storage survives reload but does not provide cross-device recovery or survive deliberate storage deletion. Legacy direct RPCs remain callable for older clients and do not provide this receipt/cancel protocol.
