## Per-session execution contract

- Start from the existing Founder OS command and its canonical repository IDs;
  read this checkpoint and the relevant queue rows, not the entire chat history.
- Record the current branch, base SHA, files owned and exact acceptance outcome.
- Implement the next authorized bounded packet. Do not stop at writing another
  plan, require repeated approval for reversible work or recreate existing suites.
- Use deterministic local checks and existing test harnesses before consuming
  build/render/provider credits. Reuse valid results until a relevant change.
- Preserve existing authorization and spending limits. Subscription access does
  not establish a background executor or an unlimited API budget.
- Persist checkpoints after meaningful commits and before ending: requirement
  IDs, branch/PR, last-good commit, checks, actual blocker, rollback and next step.
- An inactive turn is not ongoing execution. A future worker requires an actual
  supported runner, scoped credentials, leases/heartbeat, retry limits, budget
  controls, cancellation and durable receipts. Never store secrets in documents.
- On failure, fix the bounded cause or move to an independent unblocked task;
  preserve the failed result. Do not repeatedly rediscover or rerun the same job.
- Source, controlled tests, preview, production, native artifact and provider
  delivery are distinct evidence. A status edit alone never supplies proof.
