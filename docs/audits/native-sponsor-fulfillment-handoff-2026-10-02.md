# Native sponsorship fulfillment handoff

Native Festival already has real offer/application management. Its approved sponsor entries now offer a deliberate browser continuation for the accepted fulfillment workflow, rather than reimplementing its contract or losing application context in generic Creator Studio. The new component captures actor/workspace, refreshes the real SessionClient token, rechecks scope and reads the exact server capability/application before opening a fixed Zoi URL. Only opaque workspace/event/application IDs and a canonical offset are included. The receiving browser independently authenticates, validates current role and exact approved application, then mounts the shared fulfillment surface. There is no transferred token or assumed browser login.

The capability reader belongs to the separately reviewed binding migration; without it, native cannot open the handoff and browser cannot read or write Creator fulfillment. The suite wrapper preserves the captured surface across asynchronous module loading and ordinary Festival routing remains available. Duplicate identity query keys and noncanonical offsets are refused. Changed actor/workspace, unmounted or replaced surfaces and expired refresh fail closed before and after waits. Cancelled, foreign-event and downgraded-role sources cannot proceed.

Evidence: Expo57 versioned documentation read; actual React Native component compiled with local Expo57 fixture and exercised390/1440, then its emitted URL traversed the actual Festival suite wrapper/receiver/shared fulfillment module with controlled contracts. `/tmp/native-sponsor-browser.log` and `/tmp/native-sponsor-handoff` retain both widths and negative journeys. The native fixture initially let its root grow to intrinsic text width; binding its test viewport to the device width resolved that fixture-only overflow, now asserted. Latest native screenshot inspected and text wraps without horizontal overflow. Native SessionClient refresh tests use the actual client. Combined route/native/festival/snapshot tests and mobile typecheck pass. Shared sponsor browser journeys and18 isolated PostgreSQL groups pass separately.

Boundaries: no installed iOS/Android binary, live provider, real customer write or production schema apply was exercised. Browser sign-in is separate and may be required. The accepted approval/cancellation invariant is not claimed live until the lead applies and verifies the capability migration. This handoff is an explicit native continuation, not a new native proof/payment screen. Original source and commercial terms remain unchanged.
