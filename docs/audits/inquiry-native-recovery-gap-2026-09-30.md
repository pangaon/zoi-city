# Native enquiry recovery assessment — 2026-09-30

The native implementation was assessed alongside the web account-lifecycle repair. `mobile/src/Inquiries.tsx` keys Customer by authenticated user/listing/thread and Inbox by user/workspace, unmounts stale components, and checks the current actor after asynchronous reads. This differs from the independently reproduced web mount leak. No claim is made that physical-device testing has accepted every native lifecycle.

Unfinished: native start/reply request nonces live only in component memory. Leaving/restarting loses recovery; reply has a discard action despite an uncertain server outcome. The new server inquiry_receipt contract can recover author-scoped identifiers, but is not yet called by native. Before claiming parity, persist nonce-only metadata in the existing actor-scoped secure request mechanism, retain uncertainty across restart/account changes, validate receipt kind/request/target and recover the actual conversation. Do not store body/names in a nonce marker or equate found:false with proof that an in-flight request cannot later commit. The new inquiry_cancel_pending contract can also durably cancel an unsaved nonce, serialized with sends; native must validate its matching cancellation or committed receipt before clearing its marker. Same-instance exact-payload retry and a deliberate unresolved state are separate paths.

Required acceptance: lost response after real PostgreSQL commit; reload with marker; no accidental replacement send; actor A→B and A→B→A; revoked business role; original customer receipt after owner transfer; malformed receipt refusal; send-confirmed/read-refresh-failed; SecureStore failure before dispatch; and real iOS/Android device/Expo verification. Native app distribution/signing remains separate from source validation and a web production deployment. No native file changed in this increment.
