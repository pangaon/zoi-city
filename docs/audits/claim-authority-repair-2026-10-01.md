## Proposed contract
Existing signatures retained. Both claim submission and admin resolution return successful scope-bound claim_id/listing_id/workspace_id and status. Pending is review only and never sets owner fields. Frontend specialist requires those bindings before offering workspace continuation. Repeated unchanged pending submission reuses the existing claim; same-current-owner settled receipt is returned only while its recorded ownership epoch still matches. Replays never perform a transfer. Error statuses include owner_admin_required, verified_account_required, entity_not_found, already_claimed, claim_conflict, invalid_decision and not_admin.

Owner/admin membership, current authoritative confirmed nonanonymous/nondeleted/nonbanned Auth email and a present active session are required to submit. No profile is silently created. Locks serialize workspace/team and listing state before authority is checked. Admin resolution locks the authoritative admin_emails settings row and current Auth/session, rechecks after waits, and verifies locked claim workspace/listing still match the lookup. Approval also checks public visibility, no current/disputed owner, current claimant account and membership authority, and the pending authority snapshot.

A private listing_claim_authority table and owner-field trigger track ownership changes, including out-and-back (ABA). No columns are added to listings, preserving unrelated full-row review fingerprints. Pending evidence binds listing epoch, workspace owner epoch, member revision, actor/current confirmed email and listing source identity. Settled receipts bind the epoch after approval. Unique indexes prevent duplicate settled listing and duplicate pending workspace claims. They fail safely rather than deleting any unexpected pre-existing duplicates.

Autoapproval is narrower: confirmed current email domain must exactly equal a syntactically valid credential-free official website root hostname. Missing sites, scoped paths, ports, credentials, personal-mail/shared/social/directory hosts go to manual pending review. Listing-email-only matches no longer grant ownership. The provider exclusion set is conservative, not a universal registry of every shared hosting provider; no claim of exhaustive provider classification. Caller p_method is only a bounded requested-method note, never trusted evidence of verification. No external messages are sent.

## Reader and direct-table follow-through
Actual catalog confirms listing_claims, workspace_members and workspaces each have RLS enabled, null ACL and no policies; authenticated INSERT/UPDATE and anonymous INSERT privileges are false. Thus actual direct-client mutation denial was checked, not inferred from isolated fixtures. The new authority table is not deployed; migration explicitly revokes public/client access and enables RLS.

Root found the actual zoi_admin_claims reader defaults to pending and compares that literal to claim_status, while valid stored status is claim_pending. Its production ACL also permits only postgres/service_role. Candidate now preserves signature/default for compatibility, maps pending to claim_pending, allowlists the five legal statuses, returns listing_id/workspace_id along with existing row details, and permits authenticated calls only behind the locked current admin-email allowlist plus verified active-session guard. Existing create/resolve core unchanged. Test suite now passes 19 groups including visible pending queue, status validation, ordinary-user denial and revoked admin session denial. This reader returns private claim email only to an authorized current administrator, preserving its existing purpose.

Replay boundary: existing RPC signatures have no request nonce. Submission deduplicates an unchanged pending claim for the same actor/workspace/context. Resolver replays expose the current matching status/scope without rewriting notes; they are state-idempotent, not a promise that a changed decision note was applied. A later note edit is not implemented by this operation.
