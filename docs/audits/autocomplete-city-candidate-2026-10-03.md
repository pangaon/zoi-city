# Global autocomplete and intentional city search, 3 October 2026

The actual production audit found two concrete defects. OPA Productions is a valid public result beyond the former eight-row suggestion request, so the six visible suggestions could never reach it for “OPA.” A URL-scoped search for Nairobi or North York also displayed “Every city” because its exact city was absent from the fourteen popular choices. Signature’s published city is North York; searching exactly Toronto must not silently equate those two cities. The retained pre-change audit distinguishes valid but omitted results from backend errors and contains the initial test-expectation/timing failures.

This candidate changes the shared autocomplete to request at most 32 public candidates and show six at a time, with Show more matches and keyboard expansion. The existing exact-name/prefix ordering, anonymous projection, category/city/country restrictions, canonical links, abort/version fencing, timeout/retry and sparse/empty behavior remain. No curated client IDs or database ranking changes are introduced. The shared module serves Explore and Map; four actual controlled keyboard/retry journeys cover both consumers.

Explore now has a country/city dialog backed by the existing anonymous explore_regions and explore_region_cities readers. It deduplicates exact country/city names across region rows, searches within the chosen country and offers explicit city, country-wide or worldwide selection. Country changes remain a draft until the visitor chooses an action. It does not save or infer a member home and does not change authenticated location preferences. Current URL cities are inserted as exact options immediately, so the displayed filter agrees with the actual search even if absent from popular choices. No new schema, geocoder or private writer is used.
