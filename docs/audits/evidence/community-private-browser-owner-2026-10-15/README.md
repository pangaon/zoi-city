# Dedicated Community private browser acceptance

This is QA infrastructure, not a product editor or a new authentication issuer.
The disabled request performs no credential or network action. The lead owns
source integration, exact trusted-main admission, actual sessions and reconciliation.
No production operation was performed by the author.

The real admitted journey opens the existing Community composer at 390px, selects
one generated 73-byte PNG and an exact synthetic accessible description, chooses
**Save private draft**, checks the real immutable asset/proof/current-session grant
and authenticated private preview SHA, removes the original local file, reloads,
chooses **Reopen saved draft**, verifies the text, description and image bytes,
and chooses **Discard saved draft**. Save uploads first and attaches the verified
asset to the new canonical draft within the same user action. There is no separate
blank-draft create control. Both original draft nonces and the upload nonce derive
from the admitted request; no replacement nonce or private draft is created.

The initial exact public feed read alone receives a controlled empty fixture to
avoid customer content. Discovery/provider requests are blocked. Private Auth,
draft, grant, Edge, Storage and cleanup traffic is never replaced in production.
The upload wrapper validates the exact FormData, known bytes/SHA, MIME, size,
purpose and nonce before forwarding the original request. The CDP fence separately
caps one upload, one exact save and one exact discard, with current source hashes.
Actual UI controls and Edge's internal grant/byte-proof mutations are separate
claims. The grant is checked against the current dedicated session ID and its
15-minute lifetime, not a grant from a different session.

Cleanup resolves/checks or cancels only the original save nonce, reads the exact
current private draft, requires the original synthetic content, image, owner scope
and version, then resolves or uses only the original discard nonce. It checks that
no active private draft holds the image before canonical Edge asset discard and
checks private object absence. Immutable draft versions, requests, grants and byte
proofs remain; discard is not deletion of audit history. No profile, post, reaction,
contact, provider, send or scheduling writer is admitted. No browser can perform
public publication or post deletion. The existing 14-boolean production Storage
packet remains separate; no wrong-byte or replay experiment is repeated here.

An unknown receipt, changed content/version/authority, cancelled discard nonce
with an active draft, interrupted cleanup or unconfirmed logout leaves acceptance
open. The finally block attempts safely qualified cleanup only; it never bypasses
media holds or replays a save. A subsequent cleanup stage keeps the original run's
result/failure file and cannot overwrite a failed run with success. If a failed
upload has no observed asset yet, a read is not proof that an in-flight Edge request
cannot later reserve it: the run stays failed and the lead must reconcile the
original upload namespace after the operation is settled. Cleanup-only purpose
can read/cancel original receipts and discard qualified original data, never open
a browser, upload or create a private draft.

Admission is only an exact public `pangaon/zoi-city` main push with one parent,
first attempt, request-file-only diff, all code/deployed web/Edge hashes and a
request lifetime of at most 30 minutes. Cleanup has one hour of expiry grace;
that grace cannot admit another upload or save. Actions are pinned to the same
immutable refs as the accepted CRM harness. Credentials remain in memory/masked;
no credential reaches argv, URLs, local/session storage files or artifacts.
Artifacts contain only fixed booleans/stages/checks and synthetic IDs. The
390px journey does not establish desktop, native, publishing or provider acceptance.
