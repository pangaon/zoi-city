<h2 id="what-changed" class="group scroll-mt-24">What changed<a href="#what-changed" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h2>
<p>We are rolling out the PostgreSQL <strong>15.19 / 17.11</strong> minor release (from 15.14 / 17.6).
It bundles five upstream security cycles and closes <strong>44 CVEs</strong>.
Four changes may require action, depending on how you use your database:</p>
<ol>
<li><strong>ltree indexes may need reindexing</strong> — a case-folding fix on multibyte/ICU databases, plus an integer-overflow fix for very deep <code class="short-inline-codeblock">ltree</code> values (any encoding).</li>
<li><strong>pgcrypto stops decrypting legacy-cipher PGP data</strong> (CVE-2026-14663) — data encrypted with <code class="short-inline-codeblock">cipher-algo=bf</code>/<code class="short-inline-codeblock">blowfish</code>/<code class="short-inline-codeblock">cast5</code> was effectively stored unencrypted and fails to decrypt by default after the upgrade.</li>
<li><strong>btree_gist indexes on float columns</strong> that may contain <code class="short-inline-codeblock">NaN</code> need reindexing.</li>
<li><strong>Custom operators with non-built-in selectivity estimators</strong> (CVE-2026-2004) — recreating them (dump/restore, branching) now requires superuser.</li>
</ol>
<p>If none of the detection queries below return rows for your project, no action is needed.</p>
<h2 id="why-we-made-this-change" class="group scroll-mt-24">Why we made this change<a href="#why-we-made-this-change" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h2>
<p>This is an upstream PostgreSQL minor release.
Staying current closes 44 CVEs (including several rated High) and picks up correctness fixes in the <code class="short-inline-codeblock">ltree</code> and <code class="short-inline-codeblock">btree_gist</code> extensions.</p>

<h3 id="1-ltree-indexes" class="group scroll-mt-24">1. ltree indexes<a href="#1-ltree-indexes" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h3>

<h2 id="what-happens-if-you-take-no-action" class="group scroll-mt-24">What happens if you take no action<a href="#what-happens-if-you-take-no-action" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h2>
<ul>
<li><strong>ltree / btree_gist:</strong> affected index searches may silently return wrong or incomplete results - no error is raised.</li>
<li><strong>pgcrypto:</strong> decryption of affected messages fails by default after the upgrade (recoverable with the <code class="short-inline-codeblock">ignore-cipher-failure=1</code> decrypt option).
The underlying data remains effectively unencrypted at rest until re-encrypted.</li>
<li><strong>Custom operators:</strong> a future dump/restore, branch, or major-version upgrade fails to recreate the operator.</li>
</ul>
<h2 id="migration-steps" class="group scroll-mt-24">Migration steps<a href="#migration-steps" class="ml-2 opacity-0 focus:opacity-100 group-hover:opacity-100 transition">#</a></h2>
<ol>
<li>Run the detection queries above for each database.</li>
<li>After upgrading, reindex each affected ltree/btree_gist index using its schema-qualified name — <code class="short-inline-codeblock">REINDEX INDEX CONCURRENTLY &lt;schema_name&gt;.&lt;index_name&gt;;</code> runs online with no downtime, but cannot run inside a transaction block.</li>
<li>For pgcrypto: re-encrypt affected values with a modern cipher (for example <code class="short-inline-codeblock">cipher-algo=aes256</code>), before the upgrade or after it using <code class="short-inline-codeblock">ignore-cipher-failure=1</code>, and consider rotating secrets stored this way.</li>
<li>For custom operators: recreate without the <code class="short-inline-codeblock">RESTRICT</code>/<code class="short-inline-codeblock">JOIN</code> clause (or with a built-in estimator), or contact support and we&#x27;ll assist.</li>
</ol>
