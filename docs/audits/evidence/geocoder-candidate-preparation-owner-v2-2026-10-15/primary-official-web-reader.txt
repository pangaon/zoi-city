L153: The Census Geocoder is an address look-up tool that allows the user to submit a single address, batch of up to 10,000 addresses, or location coordinates for geocoding. Geocoding results are derived from address ranges within the Master Address File/Topologically Integrated Geographic Encoding and Referencing (MAF/TIGER) database. Address ranges within TIGER include all possible structure numbers even though actual structures may not exist.
L154: Geocoding results are returned if the address range match score meets or exceeds the threshold for single address geocoding. Coordinate results are interpolated, or approximated, based on the physical location that the address geocoded on the TIGER address ranges. The Geocoder is available as a web interface and as an API (Representational State Transfer - REST - web-based service).
L155: The overall goal of the Census Geocoder is to provide the public with the capability to geocode an address efficiently and accurately. There are multiple options that a user can select to geocode an address with the Geocoder. For further information on use of the Census Geocoder, please refer to the User Guide or Frequently Asked Questions documents found below in the Documentation section.

L18@P2: What is the Census Geocoder?
L19@P2: • The Census Geocoder is an address look-up tool that converts your address to approximate
L20@P2: coordinates (longitude and latitude) and returns information about the address range that
L21@P2: includes the address and associated census geography.
L22@P2: How does the Census Geocoder obtain geocodes?
L23@P2: • When an address is submitted to the Census Geocoder, the U.S. Census Bureau’s Master Address
L24@P2: File/Topologically Integrated Geographic Encoding and Referencing (MAF/TIGER) System is
L25@P2: determining if the address matches to an existing street and address range. If a match to an
L26@P2: address range is obtained, the Census Geocoder will provide the location or geographic
L27@P2: information associated with that address range.
L28@P2: My address(es) did not obtain a geocode. What are possible causes for not obtaining a
L29@P2: geocode?
L30@P2: • The address or address range does not exist in our database. Reasons for this include:
L31@P2: o Address is non-residential or commercial.
L32@P2: o Housing unit may have been recently constructed and is not in our database yet.
L33@P2: o Local Addressing Authority changed the address, and changes are not yet reflected
L34@P2:  in our database.
L35@P2: o Address may be in a location where we are missing address range information.
L36@P2: o Housing unit may have been destroyed/demolished.
L37@P2: • By geocoding the address, the Census Bureau would disclose or publish information that
L38@P2: identifies an individual or business which is a violation of U.S. Code Title 13. This is rare, and
L39@P2: usually occurs in sparsely populated areas where we have a limited number of addresses in our
L40@P2: database. For more information on Title 13 click here.
L41@P2: What does each option in Benchmark do?
L42@P2: • The benchmark is the time period when a snapshot of our data was created (generally done
L43@P2: twice a year). The geocoder allows a user to choose to geocode their single or batch addresses to
L44@P2: different benchmarks that are related to different Census data products.
L45@P2: The options listed below show examples of common benchmarks the user can choose from:
L46@P2: Benchmark Description
L47@P2: Public_AR_Current Most current address range data.
L48@P2: Public_AR_ACS#### American Community Survey contains the prior year
L49@P2: address range data. These surveys are produced every
L50@P2: year.
L51@P2: Public_AR_Census#### Address range data from the specified decennial
L52@P2-3: census. 4
L53@P3: What does each option in Vintage do?
L54@P3: • The Vintage selection option enables users to select the geographies that were in place for a
L55@P3: specific survey or Census within the FIND GEOGRAPHIES options of the Census Geocoder. For
L56@P3: example, if a user selected “ACS2019_Current” the geocoding results returned by the geocoder
L57@P3: would reflect geography in place at the time of the 2019 American Community Survey (ACS). In
L58@P3: this example, any geography that did not exist or changed after the 2019 ACS benchmark (such
L59@P3: as a city changing a boundary), would not be included in the results returned by the geocoder.
L60@P3: For more information on Vintage, refer to Appendix B in the Census Geocoder User Guide.
L61@P3: How can you display additional Census Geographic information in the geocoder results?
L62@P3: • A user can access all available Census Geography for the matched address by adding &layers=all
L63@P3: to the end of the URL associated with the results. The URL below displays how using &layers=all
L64@P3: will produce expanded results.
L65@P3: https://geocoding.geo.census.gov/geocoder/geographies/onelineaddress?address=101+
L66@P3: Mariet ta+St%2C+Atlanta%2C%2C+30303&benchmark=4&vintage=4&layers=all
L67@P3: • Specific information can also be requested using the &layers=all functionality. The tables listed in
L68@P3: Appendix C of the Census Geocoder User Guide provide names of layers along with an ID
L69@P3: number for ACS or 2020 Census vintage. A user can choose layers by using the ID associated with
L70@P3: the specific layer after &layers=. These features are available for One Line or Parsed Address
L71@P3: Processing for Geographies and Geographic Coordinate options only.
L72@P3: Can I process more than 10,000 addresses using Batch Address Processing?
L73@P3: • Users who want to geocode more than 10,000 addresses using the Census Geocoder will need to
L74@P3: split their data into multiple submissions that are 10,000 addresses or less.
L75@P3: Why is the Batch Address Processing capped at 10,000 addresses?
L76@P3: • The Census Geocoder batch size is capped at 10,000 to reduce processing time.
L77@P3: • Note for users processing large batches, more than one time:
L78@P3: o When performing batch address geocoding multiple times on the same batch of
L79@P3: addresses, you may experience an inconsistency with the number of addresses in your
L80@P3: batch that successfully match and geocode.
