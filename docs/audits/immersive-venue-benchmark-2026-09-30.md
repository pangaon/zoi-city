# Immersive venue benchmark — 2026-09-30

Research from official provider pages and documentation, not a hands-on certification or a ranking of vendors. No account, paid service, purchase, capture job or integration was activated. Recommendations below are proposed Zoi work, not delivered features.

The useful target is a recognizable, furnished Parkview experience connected to the correct event layout: walk into the room, inspect the actual lounge/table surroundings, compare the stage view, then review a real offer. A white-couch rendering can communicate a proposed arrangement but cannot establish what the room looks like or which places are available.

## Eight specific features worth implementing

Priorities are dependency order, not time estimates. P0 can improve decision-making without pretending to sell inventory; P1 requires organizer-approved operational configuration; P2 requires confirmed media and commercial rights.

|---|---|---|---|
| 1 · P0 | **Enter the furnished room.** A deliberate “Explore Parkview” action opens the actual venue tour or authorized room photographs, with table-plan context retained beside it. | Matterport supports embedded spaces and programmatic control. The user rejected the existing Parkview banquet-hall tour as the wrong experience for this concert. Do not reintroduce it. Obtain an event-relevant room capture or photographs before exposing a tour; progressively load a verified viewer only on request. A measured furnished model can follow, replacing illustration only where verified. [Embed SDK](https://matterport.github.io/showcase-sdk/sdk_home.html). | Identify exact room, capture date/configuration and permitted embed. Distinguish permanent features from event setup. A split comparison is a Zoi proposal, not a claimed documented provider UI. ## Source assets and integration requirements

For Parkview, obtain or confirm the organizer's event-specific layout and the venue's authorized room capture. The useful package contains measured room boundaries, stage orientation and dimensions, columns/obstructions, seating/booth furniture dimensions, approved textures/photos, camera viewpoints, accessible circulation facts and stable source-table→inventory mapping. This is a requirements list, not evidence those inputs have already been supplied.

Keep an asset register: origin URL or upload, rights holder/permission record, source date, captured configuration, affected room/event revision and approved display scope. Permission to embed a publicly shared tour does not establish permission to extract its panorama files or rehost its3D model. Prefer supported provider surfaces until export/reuse rights are explicit. Matterport documents SDK keys/domain setup; its API documentation warns that API tokens have broad account authority and should not be shared with third parties. Server credentials must never enter the public viewer. [SDK setup](https://matterport.github.io/showcase-sdk/sdk_home.html), [API access](https://matterport.github.io/developer-docs/api/), [current agreements index](https://matterport.com/legal).

Do not assume access to Ticketmaster VFS because basic event discovery works. Do not assume3DDV commercial artwork or a Seats.io chart subscription grants rights to an unrelated venue's photos. Verify provider plan, domains, attribution, export permissions and contract-specific usage before implementation; this document does not quote unverified fees or legal conclusions.

## Practical order for the current Zoi build

First, build the supplied furnished lounge configurations beside the verified source table preferences and private group plan, keeping them distinct from a measured venue reconstruction. Add a room tour/photo experience only after confirming it depicts the relevant concert space, with readable selected-table details and mobile/list fallbacks. Next, collect approved event-specific viewpoints and compare them honestly. Only after organizer inventory, accessible positions, currency/taxes and service configuration are supplied should selection become holds, checkout or orders. Commission a measured furnished scene if the authorized tour cannot represent the event layout; do not let geometric sophistication substitute for those inputs.

Acceptance must include390px touch and desktop keyboard, reduced motion, no forced camera movement, blocked-provider fallback, lost WebGL context, low-memory handling, rotated/resized layouts, focus restoration, expired holds and account changes. These are proposed verification gates, not a claim that this research ran provider integrations or completed Zoi native parity.
