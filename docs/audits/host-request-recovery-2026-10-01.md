# Host allocation unknown-request recovery

## Scope and actual capability

Candidate only; no live schema changes, customer writes, invitations or payment calls were performed in this lane. This repairs the existing host allocation path when a request is lost before the server records a receipt. The previous client restored a nonce after reload but could neither resend its lost private payload nor safely clear it, leaving the form blocked indefinitely.

The existing client now requires Check result before offering Cancel unconfirmed request. Cancellation serializes with the original write using the same actor/request locks. If the original write completed, its authorized receipt wins. If cancellation wins, a permanent receipt tombstone prevents the delayed original write from mutating allocations. After a verified cancellation the client clears its nonce and private drafts and reloads authoritative allocations. Account changes fence late responses and clear private state.

This does not configure either concert's inventory, connect message transport, collect payments, issue admission tickets, or establish actual host ownership. Those readiness gaps remain in event-organizer-readiness-2026-10-01.md.

## Server contract

- New authenticated RPC: event_host_request_cancel(request UUID, kind text), restricted to allocate/guest/claim/release.
- Existing private zoi.event_host_requests ledger remains authoritative. Actor/request identity is immutable; cancellation stores only kind/request metadata, no token or contact payload.
- Existing event_host_allocate, event_host_guest_save, event_host_claim and event_host_release check cancellation after request and actor advisory locks. Wrong-kind reuse rejects; same-kind delayed work returns its cancellation result.
- Existing payment writers share the ledger but already reject incompatible immutable payloads, so a cancellation cannot be bypassed through a payment kind.
- Existing receipt results run current domain authorization after waiting. Allocation replay repeats organizer authorization after locks. Claim receipt recovery verifies current claimant and event ownership without storing a raw token.
- Unknown cancellation affects only the current actor's request namespace and discloses no domain record. It validates kind and uses the existing daily request budget.
- PUBLIC/anon cannot execute the new RPC; private helper is not directly available to authenticated clients.
