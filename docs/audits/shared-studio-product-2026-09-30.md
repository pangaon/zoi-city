# Zoi Studio: connected business creation

Status: product/build contract, not a deployed capability claim. Recipe private editing is the first implementation under independent review. All existing recovery scope remains open.

## Customer journey

Start from an owned business home, event, menu, recipe or campaign. Accept a short instruction, photos or video. Reuse authorized brand, offering, location, language and audience information; ask only missing consequential questions. Show real job milestones and an editable canvas, never simulated generation progress. Produce distinct drafts for each selected destination. Customer can select an element, ask for a change, edit directly, compare versions and undo. Review content and destination accounts before scheduling/publishing. Show each destination's confirmed result, pending status or actionable failure independently.

A restaurant's event footage can become a subtitled vertical video, carousel, bilingual caption, Zoi event update and email draft. A parish's service announcement can become a calendar entry, community post and newsletter draft. A musician's tour update can become destination-specific event and campaign drafts. These are target workflows, not existing integration claims.

## Shared objects and invariants

Campaigns reference canonical business, event and offer records. Never invent a price, availability, endorsement, promotion date or booking result. Changed source facts flag dependent drafts for review; published external posts require provider-specific update support and confirmation. One shared media library preserves original uploads, edits and approved derivatives. Brand assets and private business context are workspace scoped. Uploaded child/event footage needs appropriate owner-selected sharing controls. Do not infer sensitive facts about people in media.

Use structured editable content and constrained components before arbitrary executable code. Treat imported pages, uploads and model instructions as untrusted content. Model output cannot bypass permissions or directly publish. Reuse existing account/workspace, media, writer, provider and analytics infrastructure after auditing it. AI generation requires durable job IDs, estimated usage, cancellation, retry receipts and stored output. Account changes, revoked credentials, overlapping saves and lost responses must not leak content or duplicate posts/charges.

## AI account options

1. Zoi-managed AI allowance: default low-friction option, capped usage and optional prepaid top-ups. Show estimates before expensive video/image work, actual usage after completion and explicit spending limits.
2. Bring an API account: scoped server-side encrypted credentials, revocation/rotation, provider capability checks and direct provider usage billing. Never collect ordinary account passwords, browser cookies or personal chat sessions.
3. Connected consumer subscription: only where provider expressly supports the app/use case. OpenAI's current Sign in with ChatGPT docs describe optional eligible plan usage; paid/remotely hosted apps have an approval/interest path. Not enabled for Zoi and does not import chat history.

Zoi subscription pays for workspace/brand/collaboration/automation/publishing/measurement independently of inference funding. Clearly identify whose AI balance is used. No AI credits charged for manual edits, deterministic resizing, browsing saved work or retrying delivery of an already saved result. Infrastructure/media processing can have separately disclosed quotas. Failed jobs need an explicit reservation/reconciliation policy; no silent unlimited overages.

## Proposed packaging (not activated)

Free: useful limited first creation, basic claimed home, manual editing and saved preview. Studio: brand library, reusable designs, revision history, a measured AI allowance and exports. Growth: connected channel scheduling, approval workflows, campaign reuse, working analytics and larger allowance. Team: multiple seats/locations, role controls and audit history. Price only after measuring representative text/image/video costs and verifying existing entitlements; do not create conflicting billing tiers or sell unfinished integrations. BYOK does not remove the workspace subscription and must not double-charge inference.

## Release acceptance

- Real upload -> persisted original -> generated editable draft -> manual change -> save -> reload.
- Actual job progress, cancellation and recovery; one request cannot double-spend.
- Platform-specific dimensions, captions, safe areas, subtitle preview and account selection.
- Approval -> connected provider publish -> external ID/status -> reconciliation; unsupported providers offer an accurate export/handoff.
- Authorized brand and content boundaries across account/workspace changes.
- Desktop and 390px visual review, keyboard/touch editing, reduced motion and explicit native capability status.
- No claim of perfect automation or complete provider coverage; TikTok direct publishing requires scopes, user authorization and audit for public visibility.
