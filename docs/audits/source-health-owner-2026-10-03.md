# Owner website and source review

The shared Business home editor gains a useful website review panel for every authorized listing, using the existing private owner snapshot and Page details writer. Owners can inspect their saved choice, review the editable address, restore the saved public choice, or stage a removal. Existing Save page publishes the choice with the same optimistic version, request identity and uncertain-response retry behavior. No new parallel editor or writer is introduced.

The panel distinguishes an owner-selected URL or explicit clear from an imported URL, a source hold, and absent information. Published owner choices remain authoritative even on the same domain as an older flagged import. Explicit clears do not resurrect imported/base addresses. Generic scope holds use neutral review language and are not labelled malicious. Imported source hosts are displayed as text, never a suggested replacement or clickable held link. Reviewing an address does not verify ownership, fetch the website, refresh imported facts or clear source flags.

Only three runtime files change: `assets/suite/source-health.mjs`, `source-health.css`, and minimal hooks in `bizpage.js`. The existing `official-source-policy.mjs` is reused unchanged. The optional module has an honest load-failure state and a fresh-module retry; Page details remains usable if the tool cannot load. Current account/workspace/listing fences and disposal remain in force. Source flags, schema, permissions and writer bodies are untouched.

Evidence is deliberately separate. Source/authority evidence comes from the existing owner snapshot and official-source policy contracts. Eight new pure unit groups plus twenty existing owner/consumer regression groups pass. Fourteen controlled browser cases pass at 390px and 1440px: business, artist, event and church edit/save/clear/reload/public-policy cases; keyboard restoration of URL and clear; sparse data; identical lost-response retry; version conflict retaining the unsaved address; revoked account and refused private read; and optional module failure/retry. These browser receipts use controlled existing-writer fixtures, not authenticated production changes. The existing artist owner add/save/reload/public-provider/clear journey also passed both widths before the final optional-tool retry refinement.

The final screenshots use the actual shared Zoi theme tokens, including settled light mode. Phone full Page details, phone panel and desktop/light panel were visually inspected. Earlier fixture screenshots without shared theme tokens and an intermediate light-theme transition remain retained separately; they are not accepted final form evidence.

The candidate is not deployed. Authenticated production edit→save→public read requires a separately authorized test record/account; no live source or owner data was changed. A native-specific owner panel is not claimed. Source quarantine proposals remain a separate guarded review packet, and the original full-site scope remains open.
