# Appearance identity picker — source candidate

Files: `assets/suite/appearances.js`, `assets/trips/operator.mjs`, `assets/trips/appearance-picker.mjs`, `assets/trips/appearance-picker.css`, `tests/unit/appearance-picker.test.mjs`.

Existing operator already had generic public search. This change makes current workspace listings the first explicit selection, then searches the counterpart by name/type/country using `trip_discover`; it does not create profiles or assign ownership. An event workspace chooses its event then artist/creator; an artist workspace can choose its own artist then an event. Identity chips show returned city/country, never inferred locality, and exact family canonical links. Entered time/source fields survive searching and changing selection. History now formats times in the performance timezone.

Authorization and delayed responses reuse existing `privateScope`. Auth-change immediately clears private DOM; a changed `ctx.ws` is checked at RPC boundaries and by the shared scope watcher. No old response can restore the prior account's DOM. Server owner/admin and both-side confirmation remain authoritative.

Proposal retries retain an immutable snapshot and the same UUID. Session storage contains actor/workspace/request ID only. A lost response locks edits until exact retry or reconciliation via `appearance_operator`. On reload, a found ID reconciles; otherwise users may re-enter the original details under the same UUID. Existing `appearance_propose` locks the actor profile before lookup and compares creator plus initial_data, so a committed conflicting payload cannot create a second proposal. A conflict preserves the UUID and allows correcting original details. No blind new nonce or discard action. Unrecoverable corrupted markers require support; proposal records outside latest100 can still recover by exact re-entry. Loss of authorisation does not permit bypassing the workspace gate. No separate nonce receipt RPC was added.

Only first-attempt explicit status400/403/409/422 with exact known definitive refusal codes may clear an unsent/denied request marker. Ambiguous attempts and re-entry never take that path. Saved receipts must match request ID, artist/event IDs, timezone, source and instants before success. Decisions retain existing optimistic version semantics; no new backend.

Local evidence: four pure tests pass (identity/types/dedup, both directions, safe canonical Unicode paths, declared timezone). Real browser against isolated mock-RPC fixture: name search → location chip → time/source retained → lost response → same exact UUID retry → receipt/marker clear; reload nonce marker → re-enter details → same UUID confirmed; delayed search → auth change immediate DOMclear → late result stays cleared; workspacechange clears private form.390 no overflow; screenshots `.recovery/logs/appearance-picker-390.png` and `appearance-picker-1440.png` (desktop screenshot before explicit timezone-format correction). No real proposals, database writes or external messages sent. Production acceptance remains separate.
