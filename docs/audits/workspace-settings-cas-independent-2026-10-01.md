# Independent workspace settings CAS review — 1 October 2026

Review scope: candidate migrations `20261001022938_workspace_settings_cas.sql`, separate legacy-writer cutoff `20261001022939_workspace_settings_legacy_write_disable.sql`, and settings recovery behavior. No live database writes or schema application were performed by this reviewer.

## Findings and disposition

1. **Permission revocation during receipt replay — reproduced, fixed and independently rechecked.** The first implementation authorized before taking the actor advisory lock, then returned an existing receipt without checking again. In isolated PostgreSQL, hold that actor lock; launch an exact prior request retry; demote the actor while it waits; release the lock. The old candidate returned `ok:true` and the prior receipt after revocation. Current candidate reauthorizes after the lock and the same independent sequence rejects with `insufficient_permission`.
2. **Moving an AI profile between workspaces leaves the old workspace revision unchanged — reproduced, corrected and independently rechecked.** A direct `UPDATE ai_profiles SET workspace_id=B` moved the profile out of A while A's persistent revision stayed equal to the prior populated snapshot. A became empty at an unchanged revision. The trigger originally touched only the new workspace. The current BEFORE trigger rejects workspace identity reparenting; the isolated regression confirms the old workspace cannot silently become empty at an unchanged revision.
3. **Unsent save has no recovery path — code and existing fixture confirmed; cancellation recovery implemented.** Client mode `unknown` saves a nonce marker, then receives `request_unknown`. It offers only repeated status checking; fields remain locked across remount. The existing browser test establishes no resend and private-payload absence, but does not establish eventual usability. The current request RPC can explicitly cancel an absent request under the same actor advisory lock, rechecks writer authority, and persists an immutable cancellation tombstone. Late original saves return cancelled without writing. The client offers cancellation and then reloads authoritative values before unlocking editing. The isolated cancellation-before-late-save regression passes. Independent reruns also pass reverse-order cancellation after an in-flight save (returns its saved receipt without undoing it), and role revocation while cancellation waits (denies cancellation and creates no tombstone).

## Other inspected invariants

The request hash binds workspace, section, expected version and complete submitted JSON values. Actor/request identity is unique, payload changes conflict, and receipt tables/voice revision ledgers have RLS with no direct client grants. Public RPCs require authentication. Identity requires owner/admin or existing legacy ownership; voice requires owner/admin/editor. Existing-profile CAS takes profile lock before revision-ledger lock, consistent with direct-update trigger ordering. Missing-profile CAS/direct-insert races can abort one transaction; no accepted lost update was seen in the supplied isolated check. The voice revision ledger survives deletion, protecting absent-row ABA. Legacy writer disabling is a separate second-stage migration, not silently applied with schema creation.
