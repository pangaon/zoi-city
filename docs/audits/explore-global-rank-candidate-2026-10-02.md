# Global Explore ranking index candidate

This separate packet addresses the observed desktop Clear Filters `explore_search` HTTP 500 / SQL 57014 failure. It is not deployed by this specialist. The prior count, legacy-visibility and directory-order packets stay unchanged.

The lead's real database measurement is retained verbatim in preflight: the expanded unchanged global scalar SQL took 2653.994 ms. A Bitmap Heap Scan read 32092 eligible rows over 10046 heap blocks before the dedupe WindowAgg; its sort spilled 4088 KiB. Returning only 24 records still required the wide heap first.

The candidate adds one partial covering index over the reader's exact normalized name/city/canonical-country partition keys and existing verification/trust/type/name/ID ordering. It includes only raw ranking inputs, never profile, biography, logo, owner data, or copied materialized listing content. The published, clean/cleared and nonhidden predicate exactly matches both readers. Scalar/types signatures, byte-for-byte function bodies, grants, owner, configuration, locality branch, aliases, relevance, dedupe choice and pagination remain untouched. In particular nullable verification retains its existing DESC semantics; no unrequested NULL ordering correction is included.
